# 用跨场景资料学习与评价

在新增教程、改技能、选择开发样本或声称迁移效果时读本文件。普通修一张照片时，仍以[目标闭环](goal-loop.md)为入口；无需为每次修图建立完整测试集。

这里的“学习”是Agent阅读资料、总结决策及改技能，不表示用图片训练模型权重。教程数据的个人练习、内部评价、展示派生图、再分发原文件、模型训练分别记录授权；公开下载或买到教程不自动涵盖后一组用途。只做已覆盖的用途，许可未明时保留链接和待核项，不把候选伪装成可发行素材。

## 先区分任务层

| 输入与目标 | 合适的评价范围 | 必须先解决的条件 |
| --- | --- | --- |
| 已显色、源身份明确的RGB母版 | 区域诊断、意图到操作、蒙版、逐目标评价与撤回 | 实际入口接受格式、ICC/预览与源坐标一致；比较同一母版 |
| 相机RAW或天文相机子帧 | 上游准备与后期分开记账 | 校准/堆栈/显色是否真实完成及其配方；不能拿单曝光对比多曝光作者成片 |
| 线性RGB或LRGB master | 线性校准/拉伸，之后才是显示域后期 | 确认线性状态、有效覆盖及通道关系；“TIFF”不是处理阶段 |
| 广域Ha＋RGB天景，可含地景 | Ha信息与宽带显色的结合；广域结构与地景保护 | 真实Ha与RGB来源、视场/尺度/畸变对齐、混合含义与接口；与SHO窄带星云分别覆盖 |
| 独立窄带或其他多通道数据 | 真实通道组织、组合及显示目标；以后再评价后段修图 | 每通道来源、配准/共同覆盖、映射和可用接口；没有独立SII不能假造SHO |

查[当前接口边界](backend-interface.md)，按实时能力执行。缺少窄带组合、去噪、局部对比或星层时，允许学习其选择理由并提出接口需求，不得写私有处理脚本把未有能力冒充公共流程。上游经独立准备成规范RGB，只能证明后段能力；上游准备方式及其耗时也须可见。

## 学习、开发、留出按来源组隔离

一个来源组包括同次拍摄、相邻子帧、各曝光/滤镜、裁切、降采样、mask、master、再显色版本和作者完成图。它们不能分到学习与留出两侧制造独立性。另记天体/场景、作者/教程族、相机/滤镜和拍摄夜；同M31换作者是跨拍摄/作者测试，不是跨天体测试，同作者换棚屋是跨场景，不是跨作者测试。缺拍摄日期时记未知，不自行认定独立夜晚。

| 组别 | 可看什么、可改什么 | 结果如何使用 |
| --- | --- | --- |
| 学习组 | 教程、原始素材、中间步骤、作者完成图及失败例 | 提炼“画面问题→为何选操作→风险→观察条件”；参数留在案例，不写成通用默认 |
| 开发组 | 可反复试、审图、反馈并修改技能 | 验证诊断与执行改动；腾格尔和旧Sol失败永久属于已知开发例 |
| 留出组 | 独立保管者先锁输入和任务；执行者只见当轮允许信息 | 技能/模型/后端冻结后执行；看到结果后若据此改技能，该例转开发，下一版另换留出 |
| 历史回归组 | 已发现问题的输入、失败配方及固定证据区域 | 检查修复是否复发，不宣称未知场景成功 |

小型首包可按如下意图分配，**这只是分组设计，尚非已入库或已封存测试集**：简单银河教程与一份星系图文作学习；腾格尔、复杂地景和另一弥散星云作开发；另一个未用于修订的作者族中选星团作留出候选；再用无明显银河场景检验不乱增强。窄带须单独有开发和留出来源组后才谈迁移。若当前仅一个窄带例，只能报告案例学习/复现。

留出保管者可以事先核许可、来源和可解码性；不得把作者局部参数、选区或答案提示交给执行者。题目首次执行前登记哪些人/Agent读过教程、看过完成图、处理过同组素材。已知曝光、对象名称不是失效理由，但须说明测试实际隔离了什么。没有私有隔离执行环境或无法约束参考读取时，称“独立执行评价”，不用“盲测”。

## 分清参考图的角色

- 教学复现：允许完整作者步骤和作品，检查理解、转换与回放，不能当自由审美迁移证据。
- 有参考审美任务：执行者能看指定作品，先把它译成可观察关系；作者配方/中间mask仍隐藏。目标图与原素材不配对时，不要求恢复其专有细节。
- 无参考任务：只给自然语言意图及源图；作者完成图封存至候选冻结后供审查。执行者不得浏览同一数据的答案。

参考作品是一种解法，不是唯一颜色真值。必须记它是否用了额外曝光、滤镜、另拍地景、几何合成、手工修复或生成内容。数据不等量先修正对照条件；保留用户原意，并将确实无法比较的目标标“证据不足”。生成参考只给审美关系，不允许像素/新结构进入真实作品。

## 每次前向评价

1. **冻结任务。** 登记模型/技能/后端版本、源hash与上游配方、参考可见性、自然语言目标、可用操作和运行/交互预算；预算一致才比较效率。先按基线选全图和必要固定区域，包含目标区、保护区及边缘/弱信号等压力区，不能事后只挑成功局部。
2. **执行闭环。** 按[目标记录](goal-loop.md)保存每轮区域、基线证据、预期关系、保护要求、可观察条件、状态和下一动作。状态沿用未做/改善/达成/退化/证据不足；同时比较原始基线、上一最佳与当前。允许撤回失败分支，不因操作次数多或文件导出成功就记完成。
3. **冻结候选再评图。** 独立评价者看相同色彩管理的全图及同坐标尺度局部；隐藏候选所属模型/技能版本，交换左右位置。先逐目标判断，再记整体观感。使用用户或多位评价者时保留分歧；执行Agent自己的审美判断单列。
4. **分别报工程与摄影证据。** 调用/配方/源保护/实际mask和可编辑回放是否成立是一层；目标改善、细节保留、伪影及色彩协调是另一层；用户是否喜欢另记。只读诊断不等于执行成功，算子探针不等于摄影成功。
5. **决定下一轮。** 有退化先查显示/色彩、实际操作与mask、Agent选择和源信号。一次失败不证明素材极限；需要的操作已验证正确而目标仍冲突时，才提出有证据的能力需求或目标降级，沿用原意并说明差距。

| 场景 | 目标与保护的额外检查 |
| --- | --- |
| 银河＋简单地景 | 银河/气辉/暗天关系；亮迹与亮星；地景形态和地平线过渡；不把气辉一律当偏色 |
| 复杂地景 | 树枝/叶孔/屋檐/栏杆的覆盖、串色和明暗光边；补光与天空关系；局部“更亮”不能掩盖接缝 |
| 无明显银河/多云星野 | 是否尊重存在证据，保留云与天空的区别；没有主体不强造一条银河或硬套冷暖分区 |
| 弥散星云/反射尘埃 | 亮核、弱外层和背景的关系；细丝/暗尘带是否被消噪或中和吞掉；局部锐化是否造纹理 |
| 星系 | 核心到外盘连续性、尘带和周边背景；不能以剪黑外围换“立体感” |
| 球状/疏散星团 | 密集核心/稀疏外围、星点大小与色彩、亮核饱和；没有弥散主体时不强加局部结构增强 |
| 广域Ha＋RGB天景 | 弱Ha与宽带星色/背景的关系、跨滤镜错位和彩晕；有地景时检查串入地景及地平线过渡 |
| 独立窄带 | 各滤镜来源和映射可追溯、错位彩边/覆盖边、弱通道结构；显示色偏好与物理通道真实性分开 |

保护区允许什么变化由任务预先说明。不要把“所有星点数值不变”或“背景必须中性/纯黑”设为全部场景通用规则。数字检查服务具体风险：例如新增剪切、蒙版边界残差、实际权重或回放差；像素接近作者JPEG、平均亮度上升、全局对比更大，都不能独自代表审美进步。

## 学到什么才值得改技能

把建议写成带条件的决策，并找一个不同场景检查其不适用边界。例如“为了显出星系外盘，选择只影响目标亮度段的曲线或保护核心的mask；若形成核心光环则回退并查覆盖/过渡”，不能只记作者曲线坐标。每条改动应指向已有失败、跨例收益或更清楚的能力边界；未经执行的只标理论建议。

要声称技能带来提升，使用同输入、同模型、同后端、同预算的对照，比较冻结技能与无该技能/上一技能版本；记录重复运行差异，按独立来源组报告。旧Sol单次失败与新Agent单次成功混有模型、工具和信息量变化，不能证明技能单独有效。样本少时逐例报告，不给虚假的总体成功率。

最小案例记录可直接复用：

```text
案例ID / 来源组 / 场景、作者、拍摄夜、设备与滤镜（未知明示）
教程与数据入口 / 实际读到章节或视频时间 / 作品实际看过范围
许可依据及允许本次用途 / 包体取得和hash / 输入阶段及颜色、通道、尺寸
作品配对关系及额外输入 / 学习、开发或留出 / 历史接触与参考可见性
冻结模型、技能、后端与预算 / 用户原意 / 逐目标记录与固定证据区域
实际调用、mask、配方、候选和回放证据 / 原始、上一最佳、当前比较
工程状态 / 每目标摄影状态 / 独立评价与用户审美 / 归因和下一动作
```

候选资料目录与当前通过状态放项目报告，不固化进此通用协议。新增候选、读过教程、首次只读应用、完整前向执行及跨场景效果须始终分别表述。
