# 目标、比较与下一动作

本文件是 Agent 工作记录格式，不是执行器 JSON schema。优先使用已提供的会话/反馈记录能力；工具不支持完整诊断时，在该任务允许的输出目录保存伴随记录并关联真实会话与候选。不要给配方添加未知字段，也不要把整本账本塞进有限长的 `intent`。

## 一张照片的一份意图记录

保留用户原话、后续纠正、参考来源与作用、当前优先级。后续目标修订追加理由，不覆盖原话。将“参考中令人喜欢的关系”和“当前源确实有的对象”分开：参考可有耀眼银河，本图未必能确认银河；不得据参考绘制一条亮带来完成任务。

源记录至少指向实际源身份/尺寸/编码/ICC及同域基线；候选记录关联实际配方、蒙版资产、后端配置与回执。显示预览需能追溯到该候选，不采用另一路调过色的图冒充。

### 可复制的目标卡

```text
目标 ID / 用户原话及版本：
区域：对象、源像素坐标或登记的区域/蒙版 ID；存在依据及判断来源。
基线证据：原始基线的整图/局部链接；现在可见什么，未知什么。
预期关系：谁相对谁更亮、更有层次或更冷暖；哪个性质需要改变。
保护要求：对象、范围和性质；区分数值不变与可见关系保持。
可观察达成条件：在哪个尺度看见什么；哪些反例使该目标不能通过。
优先级与依赖：主要未达 / 次要 / 可选；需先解决什么，用户已有哪项取舍。
本轮需要看见的推进：当前差距是什么，什么可辨变化才值得一个候选。
当前状态：未做 / 改善 / 达成 / 退化 / 证据不足。
下一动作：有理由的操作、诊断对照、能力请求或停止；对应证据。
```

同一目标可有明示子项。比如“沙丘更立体”通常包含坡面明暗分离，而非只要求平均亮度增加；若同时要求暖色，则颜色是另一个可检查子项。亮迹的“突出”可指相对背景显眼程度，不预先等同增加其峰值。模糊形容词应转成关系，不能捏造用户未指定的数值标准。

“保护”必须可操作。用户若要求某区域像素完全不动，应验证最终无损文件相应区域零差；用户若要求星色/形态自然，则比较同星核心与周边。硬冻结整个亮迹走廊在背景改变时可能留下暗带，数值保持不能代替关系检查。当前没有独立亮迹层时不得许诺有符号残差保真。

### 每轮的最小记录

```text
轮次 / 当前源与基线 / 上一最佳候选 / 本轮候选：
本轮假设：画面问题 → 操作与范围 → 预期变化；为什么这一步有用。
实际改动：真实操作 ID、参数/顺序变化、蒙版 ID/版本；未执行项及原因。
验证附件：渲染/颜色/蒙版/重开回执，整图及固定局部；未取得项。

目标 | 对原始基线的状态与证据 | 对上一最佳的改善/持平/退化/不明 | 保护检查 | 下一动作

候选决定：保留为最佳 / 暂存备选 / 撤回 / 技术失败；理由。
用户反馈：原话、针对哪个候选；没有反馈则明确未取得。
主要目标覆盖：哪些已尝试、哪些尚未尝试或被依赖阻塞；下轮为何选此项。
```

“改善”表示向原定关系推进但未全部满足；“达成”要求该目标条件与保护项都已看过/验过；“证据不足”用于缺视图、尺度、可信回执或观察无法支持结论。算法/工具异常单列技术失败，不伪装成审美不喜欢。

## 推进力度与分区优先级

第一次温和试验用于确认作用方向、范围和副作用；它不是所有后续候选的力度上限。确认方向后，围绕同一目标比较效果可辨的候选：维持蒙版/机制，用较弱与较强作用判断改善在哪开始、缺陷在哪出现，再选符合目标的取舍。没有必要每张图都执行固定档数或参数倍数；范围由本图响应决定。强档若有缺陷，保留作边界反例，不能因此退回几乎无效并宣布素材有限。

有附带变化时先判断失败发生在哪：目标内也过强，还是目标内合适而作用到了别处。前者比较响应/力度，后者可固定有效力度修范围，保留对主要目标的进展。对“亮度范围×空间区域”的处理，分别记录两个范围来自何处，检查相交后实际覆盖；亮度相似不等于对象相同。不要一边大幅缩范围、一边减曲线，再把差异都归因于其中一项。

区分三个尺度的进展：适屏能否看出主体/辅助区的关系，区域内部能否辨出坡面或云气层次，原尺寸有无颗粒/星形/边界损伤。整体主次仍弱时，反复改一个小角的颜色不构成对主要目标的认真尝试。局部结构操作也不能替代需要的大尺度调子分区。

有限预算优先覆盖仍未尝试的主要目标及其依赖。若多个目标共用一步，写明共同机制；若只为修复上轮新增缺陷，明确这是纠错而非原目标进展。连续几轮只围绕同一小区调整时，回看目标表：是否已把“保护成功”误当整项完成，或让小缺陷占用了全部预算。用户已认可的颜色/构图作为新分支的保留条件，只有相关失败证据才重新打开。

保护要落实到性质，不自动冻结整个区域。例如帐篷需保褶皱与亮部层次，仍可调整其周边主次；流星需保轨迹/颜色时，可在正确配对下改变背景并重合成；沙丘需保夜感，不表示永远不能提亮坡面。物理上或数值上必须不动的范围仍照合同验证。

预算结束而目标未达时，交最佳候选与未达原因；不能把剩余目标删掉来宣称完成。若还在授权预算内且有能区分原因或明显推进目标的下一步，就继续执行。

## 比较怎样具有判断力

- 原始基线避免逐轮适应过饱和、发灰或过亮；上一最佳用于判断新增一步是否值得保留。失败候选可作为反例，不能替换这两个参照。
- 先登记相关视图，再看候选；新增可疑区域后追加检查，不移除原先难看的区域。坐标用源像素并保留映射；整图缩放不会验证细星和薄光边。
- 看整图时评估焦点、夜感、冷暖关系与连贯性；看原尺寸时分别检查已有结构、微弱细节、噪声、亮暗端和边缘。返回整图确认局部优化没有破坏主次。
- 目标包含立体感或形态对比时，可读亮度增加不等于达成。对照源与候选中已有的亮坡、中坡、暗痕等代表区域，确认它们之间及内部的明暗差没有被选择权重与曲线的组合压平；必要时用少量区域测量区分整体提亮与关系改善，不要求每张图固定统计。参考仅提供目标关系，不能据此补画源中未见的亮面或纹理。
- 可以测同一无星背景小区的亮度、同一亮星的核心/外圈、沿山脊的剖面或新剪切位置，但要写明方法、域、区域与用途。背景更平、边缘差更小、饱和度更高、星更少、参考相似度更高都不是通用成功指标。
- 参考构图/细节不同，不做像素拟合或拿差分证明可恢复性。仅比较可迁移的视觉关系；同一缩图中似乎相同的星点数量也不是身份对应。
- 核查最终 TIFF 的变化；JPEG压缩与缩放差异不作为零差证据。若图像工具重采样或不明确ICC处理，保留其“视觉线索”身份，不据此给色彩或全幅细节发证。

## 未达成时如何继续

先写“看到了什么”，再写解释。下表没有固定排队顺序：选最能区分当前解释且成本合理的检查。

| 可能限制 | 有辨别力的检查 | 允许的结论与下一动作 |
| --- | --- | --- |
| 颜色或预览错误 | 空配方是否同域；ICC/TRC/位深/页数/显示链是否一致；实际TIFF与预览是否同候选；同位置是否一致变化 | 技术错误时修复链路并重评。未解决前不把偏色归因于照片或用户审美。 |
| Agent 决策错误 | 禁用可疑操作，回原始基线；固定实际蒙版，只改一个可解释变量；查看直方图区间、区域选择和叠加顺序 | 若目标变好或伪影消失，修正决策。一次撤回不能证明所有同类操作无用。 |
| 后端能力或表达不足 | 核对真实能力；单调点映射是否无法区分同亮度的星/云气；现有蒙版是否无法表达对象边缘；是否缺少相应尺度的算子 | 形成能力需求，并继续与缺口无关的目标。已装GIMP或工具菜单有同名功能不等于产品具备该能力。 |
| 素材信号不足 | 在源的同位置原尺寸局部查看结构、剪切/模糊/噪声；在正确域下做针对目标、机制适当的受控处理；排除上述可解释因素 | 只对受检区域/尺度提出有限结论；例如某片已剪切核心无可辨层次。无合适算子或无对照时写“尚不能判定”，不下“素材已到极限”结论。 |

允许多个原因并存。区分“原图已有，尚未修复”和“本轮新增”；提高可见度会暴露原有噪声，也可能造成新的色块，二者不能合并免责。

若继续调参不再产生可解释收益，回到最佳配方，选择新的机制对照、修蒙版、能力请求或明确交接。无需规定每张图固定迭代次数；用户给定预算时在预算内优先能区分原因的实验。不可无期限盲搜。

### 能力需求要能被实现者验证

```text
未满足目标与受影响区域：
源/最佳候选/失败对照及实际调用：
当前操作为什么不能表达目标：区分未提供、未验证、已测仍不足。
需要的效果与约束：作用对象/空间尺度、必须保留的结构/色彩/亮迹。
建议最小接口语义：输入域、蒙版/图层、参数单位、输出与回放关系。
最小验收：受控信号 + 原图局部 + 整图副作用；检查什么才算解决。
继续方案：可完成的其他目标；当前最佳；尚未承诺的效果。
```

例如，星点与银河细节亮度重叠，曲线一并放大两者：可请求“在明确尺度增强弥散结构、保护已识别点源与亮迹”的能力，并要求亮星光晕、暗环、弱结构保留和重合成证据。不要只写“需要高级滤镜”，也不要据此自动开启去星研究、安装插件或写临时像素处理脚本。

### 提出可达替代时

记录原目标、已尝试操作/对照、支持限制的证据、尚未排除原因、可达替代、放弃的具体效果。用户未认可替代时原目标继续为未达成；可以交付当前最佳供其比较，但不能改标完成。降低目标不是降低验证要求。
